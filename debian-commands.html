Bezpecny postup SSH hardeningu (krok za krokem)

Pokud udelate chybu v SSH konfiguraci, muze se stat, ze se uz na server nedostanete. Postupujte presne v tomto poradi a vzdy testujte v nove SSH session pred zavrenim te stavajici.

  1. Prihlaste se na server jako root (nebo sudo uzivatel) 
    ssh root@IP_ADRESA
  2. Vytvorte noveho deploy uzivatele s SSH pristupem 
    adduser deploy
usermod -aG sudo deploy
  3. Zkopirujte SSH klic roota na noveho uzivatele 
    mkdir -p /home/deploy/.ssh
cp ~/.ssh/authorized_keys /home/deploy/.ssh/
chown -R deploy:deploy /home/deploy/.ssh
chmod 700 /home/deploy/.ssh
chmod 600 /home/deploy/.ssh/authorized_keys
  4. Otevrete NOVOU terminálovou záložku a otestujte login jako deploy 
    ssh deploy@IP_ADRESA
sudo whoami  # musi odpovedet: root
    ⚠ Nezavirejte puvodni SSH session dokud nestestujete pristup!
  5. Zálohujte SSH konfiguraci 
    sudo cp /etc/ssh/sshd_config /etc/ssh/sshd_config.bak
  6. Zakažte root login a prihlaseni heslem 
    sudo sed -i 's/^#*PermitRootLogin.*/PermitRootLogin no/' /etc/ssh/sshd_config
sudo sed -i 's/^#*PasswordAuthentication.*/PasswordAuthentication no/' /etc/ssh/sshd_config
  7. Zkontrolujte konfiguraci a reloadujte SSH 
    sudo sshd -t          # musi byt bez chyb
sudo systemctl reload ssh
  8. V NOVE session otestujte, ze root login uz nefunguje 
    ssh root@IP_ADRESA    # musi byt odmitnut
ssh deploy@IP_ADRESA  # musi fungovat
  9. Nastavte fail2ban a UFW rate limit 
    sudo apt install -y fail2ban
sudo systemctl enable --now fail2ban
sudo ufw limit OpenSSH
  10. Hotovo – server je zabezpecen
    ✓ Prihlaseni pouze pres SSH klic jako deploy uzivatel.
    ✓ Root login zakaz.
    ✓ Hesla zakaz.
    ✓ fail2ban blokuje brute-force.
    ✓ UFW omezuje opakovane pokusy.
